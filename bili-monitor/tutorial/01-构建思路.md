# 01 构建思路

面向入门读者，解释这个项目"为什么长这样"。技术细节见后续章节。

## 1. 需求是什么

- 持续监控约 10 个 B站直播间（同接 100-200 量级、每天播 4-6 小时）
- 记录：开播/下播时间、礼物收入（含 SC/舰长）、弹幕明细、用户互动与分层
- 网页查看数据，房间名单可在页面上增删
- 跑在一台 2 核 / 1.7GB 内存的小服务器上，7×24 不间断

## 2. 技术选型与理由

| 选择 | 理由 |
|---|---|
| **blivedm**（Python 库） | 连接 B站弹幕 WebSocket 的现成实现。B站协议是私有的、经常变动，自己写不现实；以库依赖引入、不魔改，方便跟上游升级 |
| **SQLite**（WAL 模式） | 单机单写入者场景最简单可靠，零运维。写入量估算：10 房间峰值约 80 条/秒弹幕，批量入库毫无压力 |
| **FastAPI + Jinja2 + ECharts** | 页面布局自由（自定布局图），比 Grafana 灵活且省内存（Grafana 常驻 300-500MB，本机只有 1.7GB） |
| **采集/Web 拆成两个进程** | 互不影响：改版 Web 不中断采集；采集崩溃重启时历史数据仍可查。SQLite WAL 支持"一写多读"跨进程 |

曾考虑过 Grafana（放弃，见上）、Docker（放弃，1.7GB 内存机器直接 systemd + uv 更省）。

## 3. 架构分层

```
blivedm（WS 连接，每房间一个）
   │ 回调（弹幕/礼物/SC/舰长/同接/高能榜）
   ▼
EventRouter（handler.py：只解析+入队，不碰数据库）
   │ asyncio.Queue
   ▼
Writer（writer.py：唯一的写库者，批量事务）
   ▼
SQLite data/live.db（WAL）
   ▲
   │ 每请求只读连接
FastAPI（web/app.py）
   │ Jinja2 模板 + ECharts
浏览器
```

三条关键设计：

1. **回调只入队**：弹幕高峰每秒几十条，如果每条消息直接写库会把 SQLite 打满；队列 + 每秒批量 flush 把写入合并成大事务。
2. **Writer 是唯一写者**：避免并发写锁；Web 进程的"房间增删"写操作极少，靠 WAL + busy_timeout 共存。
3. **房间状态机**：WS 连接 7×24 常驻（未开播也连着，能收到场外礼物）；开播/下播只由轮询房间 API 判定，带 10 分钟宽限（防主播调网误判）和"重启收养遗留场次"（服务重启不拆场）。

## 4. 关键决策记录（踩坑换来的）

完整版见 `docs/TECH-SPEC.md` 第 2.1 节（实施勘误 1-31 条），最关键的几条：

1. **B站 HTTP 接口有风控**：默认 aiohttp UA 直接 412，必须浏览器 UA + 登录 cookie。
2. **真实同接能拿到**：直播间页面右上角"房间观众"来自 WS 的 `ONLINE_RANK_COUNT` 消息，blivedm 忽略了它——打补丁接管后即为真实同接（与页面数字一致）。
3. **弹幕打码与登录身份**：B站对匿名弹幕连接打码用户名（超***、uid=0）；带有效 cookie 以登录身份连接则全量完整昵称。cookie 失效的表象就是"弹幕全变打码"，配套了 6 小时保活自检。
4. **舰长价格单位是金瓜子**：`USER_TOAST_V2.price` 要 ÷1000 才是元（138000 瓜子 = ¥138 舰长首月）。
   且 price 跟随**实付价**而非标价——B站大航海首开/续费折扣不同（实测：舰长首开 ¥138、
   续费 ¥168；总督原价 ¥19,998/月、在任总督续费价 ¥15,998/月）。实测一房间
   总督 3 个月续费实录 ¥47,994（=15,998×3），与购买页"非在任价"¥51,994
   （=19,998+15,998×2）差 ¥4,000 即由此而来，消息与折算均无误。
5. **服务器连不上 GitHub**：blivedm 的 git 依赖在服务器拉不下来，改为本地构建 wheel（`vendor/blivedm-1.1.7-py3-none-any.whl`）随项目分发。

## 5. 数据口径（页面显示的数字是什么意思）

- **同接（房间观众）**：WS 实时推送，与直播间页面右上角一致；B站不再对外提供其他口径
- **看过人数**：本场累计真实观看数（接口轮询）
- **营收**：礼物按实付金瓜子 ÷1000，SC 直接是元，舰长按消息价格折算（自动续费不计——无消息推送）
- **用户分层**（v0.5 定稿口径）：核心=舰长/提督/总督，或场均送礼 ≥10 元；活跃=任一单场弹幕 ≥10 条；普通=其余（详见 [06-v0.5功能：登录双角色与运营功能.md](06-v0.5功能：登录双角色与运营功能.md) 第 4 节）
- **统计窗口**：观众构成/SC/礼物按"本场"（未开播时显示上一场），用户画像按近 30 天
