## 1. 需求与最终形态

一句话概括：**开启开关后整场自动录，直播中随手截片段，录完手动打点
切片，全部内容按日期归档、选集式回看。**

- **自动全程录制**：总览页每房间「全程」开关；开播自动起录、下播即时
  收尾（不等场次 10 分钟宽限），短时间上下播产生多段录像（每段独立完整）
- **直播截取**：自动录制进行中，replay 页大按钮回归空闲态——点击开始
  截取当前直播（在自动整场流上打墙钟起点标记），再点停止即把这段切出，
  挂到当天板块
- **打点切片**：录播成片可在抽屉里打点（设为起点/终点或手输时间），
  无损快切出独立 mp4
- **注释体系**：录播与切片都可多人注释（署名、仅本人可改删）
- **归档与回看**：全部录制（自动整场 + 迭代前手动歌切 + 孤儿切片）按
  日期倒序分组；每场一张组卡：左侧常驻播放器，右侧 B 站选集式按钮列表；
  左侧固定搜索栏（搜索只列结果、不过滤主界面），点击结果定位板块

## 2. 数据模型（db.py）

| 表/列 | 作用 |
|---|---|
| `rooms.auto_full` | 自动全程录制开关（总览页切换，capture 30s 对账感知） |
| `recordings.source` | `auto` / `manual`——归档分组与起录画质依据 |
| `manual_clips` | 切片行：偏移模式（`start_sec/end_sec`）或直播截取模式（`start_wall/end_wall` 墙钟） |
| `manual_clip_notes` | 切片注释（FK `ON DELETE CASCADE`，切片删除随删） |

三种归档组（`GET /api/rooms/<房>/auto-recordings` 输出）：

| kind | 条件 | 左区 | 右区条目 |
|---|---|---|---|
| `full` | `source='auto'`（任意时长）或手动行时长 ≥ `standalone_clip_max_sec`（默认 1800s） | 主播放器 + 打点入口 | 置顶「本场录播」+ 分割线 + 按时间序切片 |
| `standalone` | 同日短手动录制（歌切等） | 占位板块「独立片段收录」 | 歌切条目（etype=rec，走录制接口） |
| `orphan` | manual_clips 的源录制行已被水位清理 | 占位板块「切片容量超服务器容量预警线，全段录播已删除」 | 切片条目（etype=clip，走切片接口） |

> 排坑记录：被下播即时收尾截断的自动录播段（如 22:24）曾被时长阈值误归
> standalone——修正为 **auto 来源恒为 full 组**，阈值只区分手动歌切。

## 3. capture 侧

### 3.1 自动起录对账（manager.py `_reconcile_auto_full`）

`auto_full_poll_sec`（默认 30s）轻量循环：房间在播 且 无本房活跃/排队
录制行 → 插 `source='auto'` 的 requested 行（qn=`auto_full_qn` 默认 150）。
幂等三条件天然覆盖：开播、直播中打开开关、capture 重启后续录。实际起录
由既有 2s `_scan_recordings` 按全局 `max_concurrent`（v1.0.0 起 5→2，
手动+自动共用总闸）执行。

### 3.2 下播即时收尾（recording.py `on_stream_gone`）

录制与场次宽限**解耦**：`poll_live_status` 检测到未开播 → 3 秒后复核
一次房间状态（防 API 抖动误切，复播则不拆段继续录）→ 仍不在播立即收尾
finished。场次本身照旧走 10 分钟宽限（数据口径不拆场）。宽限内复播由
对账循环自动起新段——接受多段录像。

### 3.3 切片执行（recording.py `run_manual_clip`）

- 偏移模式：`ffmpeg -ss <起> -i 成片 -t <时长> -c copy
  -avoid_negative_ts make_zero -movflags +faststart`（输入端 seek 秒级，
  起止对齐关键帧 ±1~2s）
- 直播截取模式：`pick_segments_by_wall` 按 `full_<id>/` 分段文件名墙钟
  挑段 → concat+remux（与高能出片同工艺；先等 2×segment_sec 让窗口尾段
  封闭）。窗口内无分段（录制恰已收尾）→ failed 提示改对成片切片
- 收尾钩子：`finalize_recording_row` 在删分段前自动封口并先行切出所有
  进行中的 live 截取（防下播竞态丢片）
- 大按钮驱动的两端点：`POST .../recordings/live-cut/start`（同房唯一、
  需在录整场）/ `.../live-cut/{id}/stop`（<min_clip_sec 标 failed）

### 3.4 磁盘安全（maintenance.py）

- 录制产物清理从每日 04:00 提为**每小时**（`hourly_recording_cleanup_loop`，
  capture/main.py 接线）——双路长时连录的日内增长必须小时级兜底
- 新增紧急清理 `emergency_disk_cleanup`：磁盘剩余 < `emergency_free_gb`
  （默认 5GB）时无视保留期/水位删最旧成品（先整场后切片；进行中分段不可删）
- 切片独立水位 `max_total_manual_clips_gb`（**15GB**，无天数过期——人工
  成果只受磁盘约束）；processing 超 1 天标 failed

## 4. web 侧（app.py）

新端点一览（权限与注释同款：监控码限本房 + 署名，管理操作收紧 admin）：

| 端点 | 作用 |
|---|---|
| `POST /api/rooms/<房>/auto-full` | 开关（仅 admin） |
| `GET .../auto-recordings` | 归档组结构（三 kind + notes/clips 聚合 + auto_full 回传） |
| `POST .../recordings/<id>/clips` | 打点切片（偏移模式，校验 0≤起<终、≥min_clip_sec、≤成片时长） |
| `POST .../recordings/live-cut/start` / `.../stop` | 直播截取开/停 |
| `PATCH/DELETE .../clips/<id>` | 切片改名/删除（创建者或 admin；processing 409） |
| `POST/PATCH/DELETE .../clips/<id>/notes` | 切片注释（仅本人改删） |

监控码白名单：`^/api/rooms/(\d+)/(recordings|auto-recordings)(/|$)` +
`^/api/rooms/(\d+)/clips/\d+(/notes.*)?$`（精确放行 clips 与其 notes 子路径，
高能弹幕 `/clips/<id>/danmaku` 保持 403——v0_10 回归测试锁定）。

## 5. replay 页（templates/replay.html）

- **左侧固定搜索栏**（400px，≤1000px 回落横条）：搜索框（60% 宽）+
  便捷按钮 chips（`SEARCH_CHIPS` 数组维护，当前「歌切」）+ 即时结果列表
  （点击 = 选中该片段播放 + 平滑滚动定位组卡居中 + 描边闪烁）。
  **搜索不过滤主界面**（归档恒全量渲染，按键零重建——视频不闪黑）
- **组卡两栏**：左主播放器（组头动态标题加粗 + 灰色副信息：录播起止
  时间 / 切片人；弹幕层复用 v0.10）+ 常驻注释区（卡片式，区内「添加注释」
  按钮）；右选集列表（置顶录播/直播中禁用占位 + 分割线 + 切片按钮，
  同组单选，进度按选中键保存跨重建恢复）
- **切片抽屉**（经典模态抽屉：transform 滑入 .28s + scrim 点击关闭 + ESC +
  顶端「收起」钮）：仅录播选中时操作区「下载 | 切片 | 命名 | 删除」；
  打点条两行布局（起点行/终点行）；开关不丢草稿（afMarks + afNameDraft）
- **重命名 popover**：气泡卡片锚定按钮下方，回车提交点外关闭；rec 走
  recordings 接口、切片走 clips 接口
- 总览页（index.html）新增「全程」开关列（与高能开关同款）

页面与 API 响应一律 `Cache-Control: no-store`（middleware；/static 除外）
——防浏览器启发式缓存让旧脚本滞留标签页。

## 6. 运维与排障速查

| 症状 | 查法 |
|---|---|
| 开播没自动录 | `journalctl -u bili-monitor-capture | grep 自动全程`；确认 rooms.auto_full=1、并发未满 2 |
| 切片一直排队中 | `grep '\[clip\]' journalctl`；capture 是否存活；源成片是否已被清理（failed 原因会写明） |
| 磁盘涨太快 | 每小时水位 + 紧急清理日志 `grep 紧急清理`；`du -sh data/recordings/<房>` |
| 直播截取失败 | 多为下播竞态（分段已删）——对成片重新打点切片即可 |
| 录播时长比直播短 | 开播头约 35s（30s 对账+2s 扫描+起流）+ 断流缺口，属既定口径 |

配置键（config.example.toml `[recording]`）：`auto_full_qn`、
`auto_full_poll_sec`、`max_concurrent`、`min_clip_sec`、
`max_total_manual_clips_gb`、`emergency_free_gb`、`standalone_clip_max_sec`。
