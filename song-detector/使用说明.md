# song-detector 使用说明

本地视频/音频「唱歌片段」识别工具：把下载到本机的录播文件跑一遍，得到
连续 ≥2 分钟的唱歌段时间清单，供 replay 切片前定位歌曲位置。
识别全部在本机离线完成，不上传任何数据。

## 一、环境准备（一次性）

- **Python 3.12 + uv**：本项目用 uv 管理环境，首次在项目文件夹内执行
  `uv sync` 即可按 uv.lock 装好全部依赖（约 400MB 磁盘，tensorflow 较大）。
- **ffmpeg**：需在 PATH 中可用（`ffmpeg -version` 能输出版本即可）。
- **模型缓存**：首次运行自动从 TFHub 下载 YAMNet（约 4MB）到项目
  `models/` 目录，之后离线可用。网络不通时手动下载
  `https://tfhub.dev/google/yamnet/1` 压缩包解压到 `models/` 下，再把
  `config.toml` 的 `[model] path` 改为该本地目录。

## 二、日常用法（在项目文件夹内执行）

### 1. 分析一个文件或整个目录

```bash
uv run songdetector analyze "D:/下载/2026-10-10 full_28 low.mp4"
# 或批量：
uv run songdetector analyze "D:/下载/某目录/"
```

进度按百分比打印；结果写到项目 `results/` 目录：

- `<文件名>.analysis.json` —— 完整结果（含逐帧分数，网页用）
- `<文件名>.analysis.md` —— 时间清单（人读），唱歌片段表：起 / 止 / 时长 /
  均分 / 唱歌尖峰 / 说话

### 2. 网页校对（推荐：边听边核对）

```bash
uv run songdetector serve
```

浏览器打开 `http://127.0.0.1:8765`：已分析文件列表 → 点开详情 →
三色时间轴（绿=唱歌分、黄=音乐、灰=说话）+ 段落表 + 播放器，
**点击任一段的起/止时间直接跳到该处播放**。

### 3. 核对类别分组

```bash
uv run songdetector classes
```

打印唱歌/音乐/说话三个类别组的实际类名（YAMNet 521 类），确认分组符合预期。

## 三、与 replay 网页联动的完整工作流

1. replay 回放页打开某场的**切片抽屉**，点「下载low以进行识别」——
   low 版落到本机下载目录，文件名 = `录播日期 录播名 low.mp4`；
2. 在本项目执行 `uv run songdetector analyze "<下载的文件>"`；
3. 回 replay 切片抽屉点「加载本地识别文件」，选 `results/` 里对应的
   `.analysis.json`——唱歌片段逐行列出，点击时间跳转播放器，按清单打点切片。

## 四、参数调整

配置文件 `config.toml`（首次使用可复制 `config.toml.example` 改名）；
不建文件则用内置默认值。常用参数：

| 参数 | 默认 | 作用 |
|------|------|------|
| `singing.enter` / `exit` | 0.30 / 0.15 | 唱歌类迟滞阈值（歌曲段按「音乐主导」判定，此组主要供尖峰统计） |
| `music.enter` / `exit` | 0.40 / 0.20 | 音乐段阈值（漏检调低 enter） |
| `music.require_low_speech` | true | 说话+BGM 段抑制（聊天误报多时保持开启） |
| `min_duration` | **120** | 连续 ≥2 分钟才算唱歌段（用户定稿口径） |
| `merge_gap` | 3 | 相邻段合并间隔（秒） |
| `[boundary]` 组 | 见注释 | 片段缺漏修形（干净碎片吸收 / 说话尾延，full_28 标定） |

改完重跑 analyze 即生效。

## 五、常见问题

- **报告 0 段**：多半是阈值太严或内容本身无歌；先用 `serve` 看逐帧分数
  分布再调 `music.enter`。
- **报「文件没有音轨」**：视频无音轨，换文件。
- **模型加载很慢**：首次下载约十几分钟（国内直连限速），缓存后每次进程
  约 30 秒；网页服务常驻进程无感。
- **跑测试**：`uv run pytest`（冒烟用例需模型已缓存）。
