# 03 部署与运维

> 服务器现状(2026-10-15 已全部部署):napcat + live-qq-notify 双 systemd 服务运行中,
> NapCat 装于 /root/Napcat(rootless),本项目部署于 /opt/live-qq-notify。

## 一、NapCat 部署(系统组件,一次性)

```bash
# 1. 一键安装(服务器直连 GitHub 不通,经加速;或本地拉脚本 scp 上去)
curl -fL -o /root/napcat.sh https://raw.githubusercontent.com/NapNeko/NapCat-Installer/main/script/install.sh
bash /root/napcat.sh --docker n --cli y     # 默认 auto 会自选可用加速节点

# 2. 收紧 WebUI 监听(默认 :: 全地址!)
#    /root/Napcat/opt/QQ/resources/app/app_launcher/napcat/config/webui.json → "host": "127.0.0.1"

# 3. OneBot HTTP 服务器:QQ 登录后写 per-QQ 配置
#    config/onebot11_<QQ号>.json → network.httpServers[] = [{
#      "name":"live-qq-notify","enable":true,"port":3000,"host":"127.0.0.1",
#      "messagePostFormat":"string","token":""}]     # 注意嵌套在 network 下!
```

**systemd 踩坑(重要)**:QQ NT 在 systemd 极简环境下会反复 `Illegal instruction` 崩溃。
对照实验结论:unit 必须补全 shell 环境,以下缺一不可——

```ini
[Service]
Environment=HOME=/root
Environment=USER=root
Environment=LOGNAME=root
Environment=SHELL=/bin/bash
Environment=XDG_RUNTIME_DIR=/run/user/0
Environment=PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin
ExecStartPre=/usr/bin/mkdir -p /run/user/0
ExecStartPre=/usr/bin/chmod 700 /run/user/0
ExecStart=/usr/bin/xvfb-run -a /root/Napcat/opt/QQ/qq --no-sandbox
Restart=always
MemoryMax=400M
```

另需 drop-in `/etc/systemd/system/napcat.service.d/quick-login.conf`(权限 600,密码自动重登):
```ini
[Service]
Environment=ACCOUNT=<QQ号>
Environment=NAPCAT_QUICK_PASSWORD=<密码明文>
```

## 二、live-qq-notify 部署

```bash
tar czf /tmp/lqn.tgz --exclude .venv --exclude __pycache__ --exclude data \
  --exclude config.toml --exclude .git .          # 本地打包(md5 校验习惯)
scp /tmp/lqn.tgz root@<服务器IP>:/tmp/
# 服务器:mkdir -p /opt/live-qq-notify && tar xzf ... -C /opt/live-qq-notify
#         cd /opt/live-qq-notify && uv sync
#         写 config.toml([db] path=/opt/replay/data/live.db;[poll] interval=15)
#         cp deploy/live-qq-notify.service /etc/systemd/system/ && systemctl enable --now
```

配置闭环(全在 bili 页面,零手工 SQL):管理页「开播账号管理」扫码登录(WebUI 地址/
token 已预填,二维码 90 秒自动保鲜)→ 测试连接在线 → 总览页给房间开「通知」+ 齿轮配群。

## 三、保活体系(2026-10-15 定稿)

| 层 | 手段 | 说明 |
|----|------|------|
| 自动 | 密码自动重登 | 被踢后 NapCat 自动 快速登录→密码登录;设备信任建立后大概率免验证 |
| 自动 | 翻转等待重连 | 通知器在翻转瞬间 NapCat 掉线时,就地每 10s 重探至多 60s,赶上重登即发 |
| 半自动 | 设备画像备份 | `/root/.config/QQ/global/nt_data/msf/machine-info.bak.*`(WebUI `CreateLinuxMachineInfoBackup`);"重登也秒踢"时 `Restore...` 恢复后重登 |
| 人工 | 页面扫码 | 管理页「开始扫码登录」,手机 QQ 扫码确认 |

口径:**错过的通知一律不补发**(宁漏发不重发);极小概率残留窗口 = 翻转后 60s 内
自动重登未完成的场景。

## 四、排障速查

| 症状 | 查法 | 常见原因/解法 |
|------|------|---------------|
| 通知没发 | `journalctl -u live-qq-notify -n 50` | 看 WARN(接口失败)/ERROR(掉线放弃)/INFO(已发群) |
| 状态恒"未播" | 手动:`curl '.../room/v1/Room/get_info?room_id=X' -H 'UA'` | 接口返回 code?**必须小写 get_info**;code!=0 会记 WARN 不再静默 |
| NapCat 发送报 EventChecker | `journalctl -u napcat \| grep -i error` | QQ 被踢/身份失效 → 重启 napcat(自动重登)或页面扫码 |
| systemd 下 QQ 秒崩 Illegal instruction | journalctl -u napcat | unit 环境变量缺失(见上) |
| WebUI token 变了 | `journalctl -u napcat \| grep -i token` | 扫码后偶发刷新 → 更新库 qq_notify_global.webui_token |
| 二维码扫了提示过期 | 管理页重新点开始扫码 | 页面已做 90s 自动保鲜,长时间挂机后重进即可 |

## 五、服务器重启后检查单

1. `systemctl status napcat live-qq-notify` 双活;
2. `ss -tlnp | grep -E '3000|6099'` 均 127.0.0.1(3000 未起=QQ 未登录,看 napcat 日志
   是否自动重登成功,失败则页面扫码);
3. `journalctl -u live-qq-notify -n 5` 正常轮询无 WARN。
