# 04 Web 界面与 API

源码：`bili_monitor/web/`（`app.py` 全部路由 + `templates/` 四个页面 + `static/`）。

## 1. 页面清单

| 页面 | 路由 | 模板 | 内容 |
|---|---|---|---|
| 登录 | `/login` | login.html | 双模式登录页：管理员账号+口令（全站读写）/ 游客码（全站只读）；登录签发 30 天签名 Cookie（v0.5） |
| 总览 | `/` | index.html | 房间列表：头像+描述/标签/直播状态/场次/时长/同接/粉丝/营收/互动，支持今天/7天/30天切换，点击行进详情 |
| 直播间详情 | `/room/{房间号}` | room.html | 主播卡（头像可点击跳B站直播间）+今日指标+同接曲线（叠加每分钟活跃用户）+所有弹幕（上限 15000 条，含表情图片与送礼记录，可搜索）+观众构成+用户榜（可排序）+SC列表+礼物列表（盲盒礼物带角标）+历史场次（显示该主播自己的"第 N 场"） |
| 场次详情 | `/session/{房间号}/{场次号}` | room.html（场次模式） | 与详情页同一界面，标题"X月X日X时直播场次详情"，所有板块按该场次过滤，用户榜按本场参与用户计算 |
| 数据分析 | `/analysis` | analysis.html | 主播下拉 + 近 7/30/90 天窗口切换；概览指标卡 + 综合数据（一行四项问答卡，v0.6）+ 观众留存 / 直播活跃度图表（v0.6）+ 营收构成径向双层饼图（v2.0.1，前 10 用户 + 其他，内圈舰队/外圈礼物）；弹幕趋势仍为占位待后续版本 |
| 直播间管理 | `/manage` | manage.html | 房间增删/暂停/恢复 + 描述/标签行内编辑（需管理员登录） |

页面为服务端模板 + 原生 JS，无前端框架；图表用本地 `static/echarts.min.js`（不走 CDN，服务器外网波动不影响）。全站未登录时页面 302 跳 `/login`、API 返回 401（登录中间件）；原「盲盒价值」页已于 v0.5 删除（映射表 API 保留作采集端兜底）。

## 2. API 一览（`app.py`）

**鉴权（v0.5 起）**：全站由登录中间件拦截——未登录页面 302 跳 `/login`、API 401；游客（游客码登录）可读全部接口，但所有写方法（POST/PUT/DELETE/PATCH）403。原 Basic Auth 已移除；`X-Admin-Token`（或 body/query `token`）等于 config 的 `admin_password` 时视为管理员的兼容通道保留，供历史脚本使用。

**读接口**（任意登录身份可访问）：

| 路由 | 用途 |
|---|---|
| `GET /api/auth/me` | 当前登录身份（角色/用户名） |
| `GET /api/rooms` | 房间名单+当前状态+描述/标签 |
| `GET /api/summary?days=N` | 总览页列表数据 |
| `GET /api/overview?days=N` | 各房间时长/弹幕/收入汇总 |
| `GET /api/rooms/{id}/dashboard` | **详情页主数据源**（`?session_id=N` 切换场次模式） |
| `GET /api/rooms/{id}/sessions` | 场次列表（分页，含直播标题） |
| `GET /api/rooms/{id}/sessions/{sid}` | 场次明细（曲线/礼物/弹幕） |
| `GET /api/rooms/{id}/users?sort=` | 用户分布与榜单 |
| `GET /api/rooms/{id}/analysis/overview?days=` | 数据分析页概览指标（v0.5） |
| `GET /api/rooms/{id}/analysis/retention?days=&ref_days=` | 观众留存：每场与前 ref_days 天观众并集的重合度（v0.6；v0.7 起对照窗口 ref_days 可切，默认 3） |
| `GET /api/rooms/{id}/analysis/activity?days=` | 直播活跃度：分钟"任一互动人数÷同接"场均与日聚合（v0.6） |
| `GET /api/rooms/{id}/analysis/qa?days=` | 综合数据：12 类问答条目（v0.6） |
| `GET /api/rooms/{id}/analysis/revenue?days=` | 营收构成：前 10 用户 + 其他的舰队/礼物收益拆分（v2.0.1） |
| `GET /api/blind-box` | 盲盒价值映射表（v0.2；页面已删，接口保留） |

**登录与账户（v0.5 新增）**：

| 路由 | 用途 |
|---|---|
| `POST /api/auth/login` | 登录（管理员账号+口令 / 游客码），签发 30 天签名 Cookie |
| `POST /api/auth/logout` | 登出 |
| `GET /api/admins` / `POST /api/admins` / `DELETE /api/admins/{username}` | 管理员账户增删（不开放注册；不可删自己/最后一个） |
| `POST /api/admins/reset-guest-code` | 重置游客码（新码仅响应返回一次） |

**写接口**（需管理员身份）：

| 路由 | 用途 |
|---|---|
| `POST /api/rooms` | 添加监控（自动校验房间存在、拉取主播名/头像） |
| `DELETE /api/rooms/{id}?keep_history=true` | 暂停监控（保留历史，可恢复） |
| `DELETE /api/rooms/{id}?keep_history=false` | 彻底移除（名单删除，明细保留但不可见） |
| `POST /api/rooms/{id}/enable` | 恢复暂停的房间 |
| `PATCH /api/rooms/{id}/description` | 修改主播描述（v0.5） |
| `POST /api/rooms/{id}/tags` / `DELETE /api/rooms/{id}/tags/{tag}` | 标签增删（v0.5） |
| `POST /api/blind-box` | 新增/修改盲盒映射 `{gift_name, price_yuan, note}`（v0.2） |
| `DELETE /api/blind-box/{name}` | 删除盲盒映射（v0.2） |

所有 `/api/*` 响应带 `Cache-Control: no-store`（中间件）——监控数据实时变化，且浏览器启发式缓存曾导致"补全头像后页面仍旧数据"的问题。

## 3. 前端交互要点（room.html）

- **自适应轮询**：`pollLoop` 按上次间隔内新增弹幕数决定下次拉取间隔（0 条→20s，10 条→10s，≥100 条→1-2s），弹幕高峰近乎实时，冷场省资源
- **所有弹幕板块**（v0.2 由"最新 200 条"升级）：API 一次返回最多 15000 条，前端
  `renderDanmaku` 用数据签名（条数+最新时间+关键字）判断是否有变化，未变化直接
  跳过重渲染——万级 DOM 不会在轮询空转时反复重建
- **弹幕搜索**：前端过滤全量弹幕（用户名/内容/礼物名），实时显示命中数
- **表情图片渲染**（v0.2）：每行弹幕带 `emots` JSON（`{占位符: {url,...}}`），
  `dmContentHtml()` 先 HTML 转义再把占位符替换成 `<img class="dm-emot">`；
  纯图片弹幕（文本为空）直接平铺显示图片
- **送礼记录混排**（v0.2）：最近 20 条送礼/SC/上舰与弹幕按时间合并渲染，
  礼物行浅橙底 + 标签 + 价值，盲盒礼物带"盲盒"角标
- **上舰礼物 ×N 展示**（v0.3）：上舰记录名已含月数（"总督x3月"，`count` 存月数），
  再按件数叠加会显示成"总督x3月 ×3"（×3 是月数不是件数）。礼物列表的
  `guardTimes()` 对上舰改按**购买笔数**（`orders`）显示 ×N（单笔不加后缀），
  弹幕流 `giftLineHtml()` 对上舰不再追加 ×N；普通礼物仍按总件数 `cnt` 显示
- **粉丝牌胶囊**：`medalHtml()` —— 牌名块与等级块统一用等级段位色（20-29 浅蓝/30-39 深蓝/40-49 紫/50+ 金，20 以下用官方牌名色）；舰队标识 `guardBadge()`（总督红/提督紫/舰长蓝）
- **SC 档位配色**：`scColor()` 对齐 B站（≥1000 红/≥500 橙/≥100 金/≥50 紫/≥30 蓝/其余绿）
- **B站图片防盗链**：`base.html` 声明 `<meta name="referrer" content="no-referrer">`，否则头像/礼物图/表情图会被 CDN 403
- **样式表版本号**（v0.5.1）：`style.css` 引用带 `?v=<文件mtime>`（模板全局 `asset_ver`）——新样式追加在文件末尾时旧缓存仍会命中同 URL，加版本号强制浏览器重新拉取

## 4. 数据分析页板块与口径（v0.6）

三个板块的数据全部由现有明细表（弹幕/礼物/互动/人气快照/场次/主播指标快照/用户画像）SQL 聚合得出，**零新表、采集端零改动**；统计窗口统一为"近 N 个自然日（含今天）"，与图表横轴逐日对齐。

- **综合数据**（全宽板块，一行四项、每项浅色卡）：12 类"问题 → 答案 → 口径说明"条目（营收最高日 / 弹幕最多场次 / 常开播时段 / 场均时长 / 同接峰值 / 单场营收峰值 / 弹幕密度 / 付费率 / 人均消费 / 涨粉 / 新观众占比 / 大航海变化），窗口内无数据的条目自动省略。指标体系参考小葫芦等直播数据平台。
- **观众留存**（两级类目轴柱状图：日为组、场为柱，无直播日留空）：
  - "场次观众" = 该场内任一互动（弹幕/礼物/SC/舰长/关注分享）的去重 uid，uid=0 脏数据排除；
  - 留存率 = |本场观众 ∩ **前 ref_days 天**观众并集| ÷ |并集人数|（回访口径；对照集合 = 本场开播前 ref_days×24 小时内所有已结束场次，允许跨出统计窗口，含当日更早场次）；
  - 对照窗口（v0.7）：板块右上角为 **3日/7日/30日/90日** 切换按钮（替代原说明文字），默认跟随页面统计窗口天数（页面切 近7天/近30天/近90天 时留存重置回同值，点留存按钮后独立生效）；接口对应 `ref_days` 参数，缺省 3（v0.6 口径）；
  - 对照窗口内无已结束场次 → 该场无柱；对照明细若早于弹幕保留期（默认 90 天）被清理，留存率会偏高——ref_days 不超保留期即可无影响。
- **直播活跃度**（每日"平均/最高"双柱）：
  - 分钟活跃占比 = 该分钟**任一互动**去重人数 ÷ 该分钟平均同接（`popularity_snapshots.viewers` 分钟均值，快照间隔默认 60s 天然对齐）；
  - 该分钟无快照或同接为 0 → 跳过（开播初期同接未推送，防除零与虚高）；场均活跃度 = 有效分钟占比的算术平均，只统计已结束场次；比值可能 >100%（快照对齐误差，罕见，不截断）。
- **板块布局**（v0.6 起）：详情页"所有弹幕""SC 列表"与数据分析页各板块行统一左右各半（`style.css` 的 `.detail-bottom`/`.detail-extras` 网格 `1fr 1fr`）；详情页用户榜"用户"列限宽 168px（v0.6 放宽 10px）。

## 5. v0.2 数据口径备忘

- **盲盒收益**：按开出的礼物计价（消息 `price × num / 1000`）；`price` 缺失时查
  `blind_gift_prices` 映射表（先开出礼物名后盲盒名），再不行按盲盒本身价值计。
  0.1 期间的旧盲盒记录保持盒价口径不改写（v0.2.1 定稿）
- **场次序号**：历史场次表与副标题显示该主播自己的"第 N 场"（`seq`，按
  `start_time` 排序的 row_number），URL 里的场次号仍是数据库 `session_id`
- **短间隔场次合并**（v0.2.1）：同一房间下播→再开播间隔 ≤ 10 分钟
  （`capture.session_merge_gap_sec`）视为同一场——复播时沿用旧场次继续记；
  历史短间隔对由每日维护幂等合并
- **分层实时性**：送礼/舰队/弹幕消息由 writer 实时跟进分层（舰队立即升核心、
  当条场次送礼累计 ≥10 元升核心、场次弹幕满 10 条升活跃），不再等凌晨 04:00
  维护重算；每日维护仍按权威口径（v0.5：舰队或场均送礼 ≥10 元核心、单场弹幕
  ≥10 条活跃）全量重算一次，两边规则见 06 章第 4 节

## 6. 常见"数字不对"排查

| 现象 | 原因与处理 |
|---|---|
| 打不开页面直接跳登录 | 未登录或 Cookie 过期（30 天），属正常；游客用游客码登录即可只读浏览 |
| 弹幕全变"超***" | cookie 失效（匿名态）→ 换 cookie 重启 capture（05 章第 7 节） |
| 同接显示 0 | 轮播间/部分房间不推送房间观众消息，非故障 |
| 收入虚高（如 138000） | 旧数据的舰长折算错误已修；若再现检查 handler `_on_user_toast_v2` |
| 盲盒收益等于盒价 | 消息缺开出礼物单价（price=0）且映射表没该礼物 → 调 `/api/blind-box` 接口补映射（页面已删）；0.1 旧记录按盒价口径保留（v0.2.1 定稿） |
| 页面样式异常/数据旧 | 强刷（Ctrl+F5）；样式已带 mtime 版本号、API 已 no-store，一般是刚重启窗口期 |
| 主播名/头像空 | 轮询会自动补全（每 2 分钟一次），等一轮即可 |
