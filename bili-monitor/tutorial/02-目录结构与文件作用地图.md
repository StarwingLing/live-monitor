## 数据库表（`db.py` 的 SCHEMA）

| 表 | 粒度 | 说明 |
|---|---|---|
| `rooms` | 每房间一行 | 监控名单（页面上增删的就是它）+ 主播昵称/头像/描述（v0.5） |
| `room_tags` | 每房×每标签 | 主播标签（v0.5，每房 ≤8 个） |
| `live_sessions` | 每次直播一行 | 起止时间、同接/人气峰值、弹幕数、营收冗余合计 |
| `session_titles` | 每场次×每标题 | 场次直播标题（v0.5，标题变更追加记录） |
| `danmaku` | 每条弹幕 | 用户、粉丝牌（名/等级/官方色）、舰队等级、内容、表情 JSON |
| `gifts` | 每笔礼物/SC/舰长 | type 区分；`is_offline` 标记场外收入；礼物缩略图；盲盒名 |
| `interactions` | 每次关注/分享等 | 高频的"进入/点赞"不记 |
| `popularity_snapshots` | 每分钟 | 人气值（加权）+ **房间观众（真实同接）** |
| `anchor_snapshots` | 每 2 分钟 | 粉丝数/看过人数/大航海数（接口轮询） |
| `user_stats` | 每用户×房间 | 画像聚合：计数、粉丝牌、舰队等级、分层 |
| `uname_map` | 每用户 | uid→完整昵称（打码还原兜底用的全局总表） |
| `emotes` | 每房间×每表情 | 房间可用表情（弹幕图片渲染，定期拉取） |
| `blind_gift_prices` | 每礼物名 | 盲盒开出礼物价值映射（price 缺失时兜底计价） |
| `admin_users` / `app_secrets` | 每账户/单行 | Web 登录账户（哈希）与 Cookie 签名密钥（v0.5） |

## 一条弹幕的完整旅程

以房间 <房间号> 的一条弹幕为例，按代码执行顺序：

1. blivedm 收到 WS 消息 `DANMU_MSG`，解析成 `DanmakuMessage` 对象
2. `handler.py` 的 `_on_danmaku` 被回调：
   - B站隐私用户 uid=0 → 用 `uid_crc32` 哈希造负数伪 uid（防止所有打码用户并成一人）
   - 打包成 `("danmaku", {...})` 放进 `asyncio.Queue`（毫秒级返回，不阻塞收消息）
3. `writer.py` 的 `_flush` 每秒醒来，把队列里所有事件归拢成一批：
   - 伪 uid 先查 `_crc_map`（uname_map 的 crc 反查表），命中则还原成真实 uid+全名
   - 一次事务写 `danmaku` 明细 + `user_stats` UPSERT（计数累加、粉丝牌跟随）+ `live_sessions.danmaku_count` 冗余 +1
4. 前端每 1-20 秒（按弹幕热度自适应）调 `/api/rooms/<房间号>/dashboard`
5. `app.py` 查库返回 JSON，`room.html` 渲染进"所有弹幕"板块（带粉丝牌胶囊/舰队标识）

礼物同理，多一步折算：金瓜子 ÷1000 = 元（`handler.py` `_on_gift`）。

## 场次（live_sessions）的生命周期

由 `manager.py` 的 `poll_live_status` 每 2 分钟驱动：

```
轮询发现开播 ──► 有遗留未关闭场次？──是──► 收养沿用（服务重启不拆场）
                    │否
                    ▼ 新建 session（end_time=NULL，页面显示"直播中"）
轮询发现未开播 ──► 进入宽限期（10 分钟内每 2 分钟复核）
                    ├──期间复播 → 日志"宽限期内复播"，场次不动
                    └──仍未播 → 写 end_time（结束时间取最后快照）
```

## 为什么有两个配置文件

`config.toml` 是真实运行配置，里面有登录 cookie 和管理口令，**绝不能进 git**（已在 `.gitignore`）；`config.example.toml` 是给人看的模板。换新环境时复制模板再填值。
